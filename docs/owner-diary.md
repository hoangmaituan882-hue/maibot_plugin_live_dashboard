# 主人日记使用说明（1.2.1）

主人日记默认关闭。启用后，插件每天在统一时间设置所选时区的00:15汇总前一天：读取面板现有时间线，过滤并整理活动事实，可选通过MaiBot官方Replyer生成日记，再保存到插件自己的持久化目录。不会自动向聊天发消息，不注入全局Prompt，不写入原生长期记忆。统一时区留空时沿用1.2.0的旧日记时区。

## 配置步骤

1. 保持原有面板地址和查询设置。在「主人日记」中启用功能。
2. 设置「管理员」为 `平台:用户ID`，多个值用逗号分隔。例如 QQ 的 `qq:123456`；实际平台名以宿主为准。管理员可以读取、生成、删除、导出。
3. 如要允许其他人查询，填写读取用户或完整聊天流白名单；满足任意一项即可读取。名单为空时只有显式配置的管理员可读取。全局用户/群黑名单仍优先生效。
4. 日记可先使用事实版。如果需要麦麦人设口吻，管理员在目标聊天中执行 `/主人日记 状态`，将返回的当前聊天流 ID 填入「生成日记所用的已有聊天流 ID」。无需设置额外模型密钥，也不会自动创建聊天流。
5. 在官方组件管理中启用 `query_owner_diary` 工具，麦麦才能在自然语言聊天中选择读取日记。该工具初次注册默认停用，原有实时状态工具仍默认启用。

配置示意（请使用插件 WebUI，或合并到已有配置，不要覆盖原配置）：

```toml
[time_settings]
timezone = "Asia/Shanghai"

[diary]
enabled = true
generation_time = "00:15"
retention_days = 90
backfill_days = 3
generation_stream_id = ""
allowed_streams = ""
allowed_users = ""
admin_users = "qq:123456"
device_ids = ""
include_titles = false
reuse_upstream_summary = false
generation_timeout_sec = 180
```

旧`diary.timezone`仅作为兼容字段保留并在WebUI隐藏。修改统一时区会改变日界线，原有日记仍保存在原时区对应的归档范围，插件不把旧日期记录自动重写成新时区。

## 命令

| 命令 | 用途 | 权限 |
| --- | --- | --- |
| `/主人日记` | 查看昨天的归档 | 读取名单或管理员 |
| `/主人日记 2026-10-26` | 查看指定日 | 读取名单或管理员 |
| `/主人日记 查看 2026-10-24 2026-10-26` | 连续读取，最多7天 | 读取名单或管理员 |
| `/主人日记 生成 昨天` | 手动生成，已有日记直接复用 | 管理员 |
| `/主人日记 重新生成 昨天` | 重新读取面板，有效事实发生变化后修订；事实版可重试模型 | 管理员 |
| `/主人日记 删除 2026-10-26` | 删除正文、事实、修订及本地导出，不会被自动补录重建 | 管理员 |
| `/主人日记 清空` | 清空当前面板和时区的日记；之后从当前日继续自动归档 | 管理员 |
| `/主人日记 导出 昨天` | 写出服务端本地 Markdown，包含完整结构化事实 | 管理员 |
| `/主人日记 状态` | 查看时区、调度设置、当前平台和聊天流 ID | 管理员 |

日期可用 `YYYY-MM-DD`、`昨天`、`前天`。尚未结束的当日和未来日期不生成日记，查询今天活动请使用时间线。导出保存于插件数据目录的 `diary/exports/`，命令返回服务端文件路径；此版本不自动上传群文件或提供公开下载链接。

自然语言示例：“主人昨天忙什么？”“翻一下10月24日到26日的主人日记。”工具只读，不会在查询过程中隐式生成、重写或删除日记。缺失日期会明确说明，仍可通过原有时间线工具查询面板。

## 保存与调度

- 默认保留最近90个已结束的自然日。每次启动、日记操作和日常调度时清理过期记录，修改保留期限后也会执行清理。
- 首次启用日记当日是自动归档起点；第二天 00:15 归档第一篇。可以手动生成启用前仍在保留范围内的日期，前提是面板还有历史。
- 停机后最多补录最近3天（可改为1至7天），不会补录早于首次启用日的日期。面板不保存的历史无法重建。
- 网络错误、鉴权失败和日期/结构错误不会覆盖已有日记。自动任务同日最多尝试3次，间隔逐步增加；管理员可明确重试。
- 没有活动片段时保存“没有足够记录”的说明；不调用模型虚构活动。没有生成会话、模型超时或输出未通过检查时，保留事实版。事实版不会自动反复调用模型，可在设置修好后手动重新生成。
- 相同日期的并发生成合并执行。重启后会检查归档，避免重复生成。配置更新或停用会取消旧生成任务，防止旧配置的结果落盘。
- SQLite 数据库为 `diary/diaries.sqlite3`。同日修订最多保留此前3个版本；按日期删除或清空也会删除修订。

## 事实与隐私

所有片段在写入磁盘或提供给模型之前过滤。日记继承设备名称白/黑名单，并可额外按 `device_ids` 限制设备 ID。设备 ID 在整理后以稳定摘要代替，避免向模型传入原始标识。

默认不保存窗口标题，不采集健康数据，不混入好友面板活动。启用标题还需原有「显示窗口净化标题」开关允许；信息关键词黑名单、NSFW 兜底和应用名称开关继续生效。改变这些过滤设置会使同一面板不符合当前策略的旧日记、修订和本地导出失效并删除，可再从面板重新整理。更换面板后，新来源不能读取旧来源日记。

日记直接消费时间线结构化数据，超过聊天展示上限的活动也参与整理；异常或超大输入会标注缺失/截断。同设备重复片段合并，跨设备重叠使用时间取区间并集，不将多台设备时长相加称为主人总活动时间。

自然语言正文是模型整理，程序另存有统计和活动证据。提示约束、敏感词和数值检查只能减少错误，不能完全证明模型正文每句话都正确；回忆时应以日期、事实统计和明确记录为准，不能把设备在线当成人在场，也不能从应用运行推断心情、成果或睡眠。

## 可选上游小结

面板的主分支没有 `/api/daily-summary`；花信分支才有。这个功能默认不使用，404、空值和无效响应会回退正常日记流程。

只有明确启用复用、允许标题及应用名称，并且没有设备/信息关键词限制时，插件才尝试读取小结，避免混合文本绕过本地过滤。成功归档后标记为“上游小结”，展示源生成时间，并说明不保证包含之后的活动；花信默认21点生成，不能当成完整一天的最终总结。即使复用小结，仍保存过滤后的时间线事实。开启该选项不修改面板配置，也不替面板配置 AI。

## 与原生流程的关系

后台写作用官方 `maisaka.reply.generate`，基于指定已有会话的人设生成并返回正文。查日记时，插件把材料交给 Planner，由其将相关日期和事实通过 `reply_reference` 交给 Replyer。无需修改 Prompt 管理或人设模板。

日记查询、后台写作与主动聊天分开；此版本不主动开启话题。日记是本地可检索归档，尚未对接 A_Memorix 的原生写入接口。
