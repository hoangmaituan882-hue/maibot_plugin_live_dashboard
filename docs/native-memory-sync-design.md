# 主人日记：原生记忆同步、麦麦评价与触发优化

状态：已搁置的设计草案，尚未实现。当前可安装版为1.2.1；本文仅保留方案参考，不表示已排期、已向麦麦记忆库写入数据或已修改主程序。

## 已核对的宿主事实

以MaiBot 1.3.15、SDK 2.16.0为基线（宿主提交 `062d45cf8bd4272ac57d7ec03fcf405e5a458211`）：

- 原生 `src/services/memory_service.py` 提供 `ingest_summary` 和 `ingest_text`；主线通过 `src.A_memorix.host_service` 接入，不加载旧的A_Memorix插件入口。
- 插件能力注册表只有 `knowledge.search`，没有公开给插件调用的记忆写入、更新和删除能力。不能假设旧 `ingest_text` Tool可以被当前插件跨插件调用。
- 原生已有受认证的WebUI导入任务接口，但它不是SDK能力。不能把管理页面的导入任务创建成功当作记忆落库完成，也不把管理员登录令牌当作插件的默认依赖。
- `ingest_text` 按 `external_id` 去重。普通文本遇到同一ID会返回 `reason=exists`，不会用新正文覆盖旧正文。因此“同一天使用固定ID再次写入”不足以实现修订同步。
- `source_type=person_fact` 会进入人物事实账本；普通 `note` 写入不走该分支。麦麦主观评价应使用有作者和时间的note，不能作为主人的person_fact。
- 服务启动阶段可能排队，记忆关闭、过滤或初始化失败可能返回跳过原因。不能只用一个success布尔值判断同步完成。

## 目标结构

同一篇日记保留三个独立部分，日期、时区、来源与覆盖范围共用：

1. **时间线事实**：程序计算设备记录的应用分布、时段、使用时间及缺口；不由模型重算数字。
2. **每日总结**：由原生Replyer按人设把事实整理成自然语言，说明观察范围。
3. **麦麦评价**：同一轮生成中的独立字段 `bot_review`，用麦麦自己的视角表达感想、关心或想继续聊的问题。评价必须能关联当日记录，允许说“我觉得/从记录看”，不能把猜测写成已发生的事。

正文建议：总结150至250字，评价40至100字，合计仍控制在原有200至400字附近。示例格式为“今日记录 / 今日小结 / 麦麦的想法”，不用额外覆盖全局人设。一次生成同时得到总结和评价，避免每天调用两轮模型。结构不合法时保留事实版，不把未分离的长文自动同步成主人事实。

模型原始输出、最终展示和同步材料分别校验。评价中的“我很想问问主人今天在忙什么”描述的是机器人的想法；不等于创建提醒或自动发言任务。

## 原生同步内容

建议每天最多两条记忆：

| 记录 | 正文 | 属性 |
| --- | --- | --- |
| 每日活动记录 | 关键时间线统计＋每日总结，去掉重复片段 | dated observation，来源为日记，明确属于某天 |
| 麦麦当日评价 | 只包含bot_review，附“麦麦基于当日设备记录的主观看法” | bot opinion，作者为bot，评价对象为主人 |

原始上百条片段继续只保留在日记，不逐条塞进原生记忆。时间线事实和日记总结属于同一组材料，不再各写一条重复记忆。默认不从评价提取“主人很懒/热爱工作/情绪不好”等人物画像标签；稳定习惯必须有多日证据和单独的确认流程，本版不自动做。

评价使用 `note`，不生成 `person_fact`、实体或关系声明。metadata保留 `kind=bot_opinion`、作者、所指人物、日期、日记版本和事实指纹；正文也写明这是主观看法，不能只依赖metadata。原生后续检索或摘要是否始终保留这种区分，必须纳入宿主集成验证，不能仅凭设置标签承诺绝不误归类。

## 归属与权限

生成会话、记忆所属会话、主人账户、bot作者是四个不同概念。主人称呼仍来自人设；原生记忆的人物关联需要显式选择一个真实账户，并通过宿主已有person接口解析，不能由模型猜QQ号或自行计算人物ID。

记忆归属只使用真实已有聊天流。默认留在选定私聊或指定会话，不复制到所有群。读取、写入都遵守原生记忆开关与过滤，`respect_filter=true`；不自动开启跨群共享、不为同步修改过滤配置。

“启用日记”“生成麦麦评价”“同步原生记忆”“允许主动聊天”分别设置。用户可以只使用本地日记。记忆停用、缺少账户归属或缺少写入能力时，保持本地归档，并给出明确的待处理原因。

## 写入与修订协议

日记保存成功后，将本次版本的同步任务和内容指纹写入本地事务发件箱；后台异步同步，聊天查询不等待写入。

- 逻辑记录键：面板来源＋记忆归属＋主人＋日期＋记录类型。
- 版本键：事实指纹＋总结/评价生成策略版本＋明确修订号。幂等重试复用同一键，不重新调用模型生成不同评价。
- 记录每次请求的external_id、native stored_ids、日记版本和返回原因。无落库证据时保留pending/queued/failed状态，不显示“已记住”。
- 固定external_id的exists只表示原记录存在，不能证明当前修订已覆盖旧正文。需要宿主桥接提供版本替换及旧记录失效能力，或明确调用经验证的原生修正/删除接口。
- 修订先检查事实或生成策略是否变化；仅浏览、重复调度、缓存命中不产生新记忆。
- 按日期删除或因隐私策略变化失效时，同步撤回本插件创建的记忆对象。需要保存可恢复的撤回任务；原生不可达时显示“本地已删除，原生撤回待完成”。
- 原生撤回必须按已验证的对象归属执行，不能按一个宽泛source删除整个聊天的其他note。不能改写或删除非本插件创建的记忆。
- 自动保留期限清理与“忘记这一天”分开：本地缓存到期不自动等同用户要求原生遗忘；是否两端按相同期限删除作为明确设置。

## 触发矩阵：什么时候处理

| 触发 | 生成日记 | 原生同步 | 主动发言 |
| --- | --- | --- | --- |
| 次日00:15到期 | 汇总前一天 | 成功归档后提交相应版本 | 不触发 |
| 重启、休眠唤醒、容器重建 | 检查最近3天的缺失任务，受启用日限制 | 恢复未确认任务，原键重试 | 不补发旧话题 |
| 管理员手动生成 | 立即处理一天；允许绕过定时时间 | 受同步开关、归属和权限约束 | 不触发 |
| 管理员重新生成 | 输入变化或原生成失败才处理 | 有效新版本替换旧版本 | 不触发 |
| 用户自然语言查日记 | 只读已归档材料 | 不新增、不重复写入 | 沿用当前正常回复 |
| 原生记忆刚启动或不可用 | 日记正常保存 | 持久化等待、有限退避，不标记完成 | 不触发 |
| 模型不可用或未配置生成会话 | 保留事实版，评价为空 | 可按设置仅同步事实；不伪造评价 | 不触发 |
| 面板没有可用片段 | 本地保存资料不足说明 | 默认不制造一条无依据的活动记忆 | 不触发 |
| 面板断网/401/异常日期 | 不覆盖已有日记 | 不能用失败结果更新记忆 | 不触发 |
| 正常群聊活跃 | 后台低并发、错峰处理 | 后台同步 | 不强插消息 |

写入和生成的失败分别重试：写入失败不重新调用Replyer。查询缓存、日记任务、原生同步任务使用各自的去重键。免打扰时段控制主动发言，不阻止安静归档；日记定时写作窗口可以独立设置。

如果宿主没有公开“当前模型忙闲”信号，不能假设插件已能检测所有会话繁忙程度。第一阶段用单任务并发、可配置写作时间和调用预算控制影响；有真实宿主信号后再增加延后调度。

## 活动场景：评价怎样变化

- 编程、文档等应用占比较高：描述工具和记录的集中程度，可以表达对项目的好奇，不断言取得工作成果。
- 游戏、影音较多：可以轻松聊兴趣，不自动贴“摸鱼/沉迷”等标签，不从窗口运行推断本人一直参与。
- 应用切换较多：只有程序计算了切换次数或分散程度时才评价这种节奏；不能从抽样片段直接估计完整切换频率。
- 记录稀疏、设备离线：明确“我掌握的记录不完整”，不推断睡眠、心情、健康或离开的原因。
- 多设备并用：保留设备来源，人的观察覆盖时长按区间并集，不能把电脑和手机各一小时说成主人活动两小时。

场景只影响总结和评价材料，不增加主动聊天频率。分类采用可配置的应用映射；未识别应用保留原名，不强行分成工作或娱乐。

## 部署环境：可靠地触发

| 环境 | 处理 |
| --- | --- |
| Windows与桌面休眠 | 使用插件生命周期调度，唤醒后对账补录；不依赖系统任务计划程序 |
| Linux/systemd | 同一套插件任务；重启后读取持久化日志，避免靠内存标记判断是否写过 |
| Docker | 持久化挂载日记与同步日志目录；显式IANA时区；地址使用容器可达的面板地址，不能假定localhost是宿主机 |
| 服务器时区不同 | 日期边界与任务日统一用日记配置时区；请求时间、事件日期和生成日期分别保存 |
| 热更新或停用插件 | 取消本地生成；已提交原生的请求保留请求身份，恢复后确认结果，不能假设取消等于远端未写入 |
| 多进程/多实例 | 默认指定单个调度实例；共享存储时增加跨进程租约和唯一任务键。仅asyncio锁不能防止多实例重复调用模型 |

## 接入路线与边界

推荐在宿主接入层增加最小、受权限保护的日记记忆桥接，封装原生写入、版本替换、撤回和状态查询，复用A_Memorix已有实现。桥接只允许本插件的命名空间、受限文本长度、真实会话、真实人物归属和本插件已登记的记忆对象。

插件继续通过RPC调用，避免直接import宿主源码、打开原生SQLite、伪造聊天消息或把内网上的管理页面当作默认写入通道。Windows、Linux、Docker共用这一协议；没有桥接时报告“当前宿主缺少日记记忆写入能力”，本地日记继续工作。

这一步涉及宿主主程序接入层。当前仅完成方案核对，未修改宿主；如果实际实施宿主改动，需按其AGENTS要求先取得许可，并提供独立可审阅的补丁，不改动A_Memorix核心实现。

## 验收重点

1. 同日、同版本的定时/补录/手动操作不会重复生成或重复写入；跨实例也能确认相同逻辑记录。
2. 旧版本不会在修订后继续作为当前记录被召回；删除/隐私变更的撤回可恢复、可核查。
3. 主观评价有作者与日期，不进入主人person_fact；没有评价依据或模型失败时允许为空。
4. queued、过滤跳过、关闭记忆、失败和实际写入分别显示；后台失败不打断正常聊天。
5. 私聊与群聊的记忆范围遵守宿主配置，主人关联不从提问者或人设自由文本猜测。
6. 休眠跨日、时区与夏令时、容器重启、网络恢复、插件热更新都有可重复验证的触发结果。
